Hệ thống Phân tích Logistics Nhân đạo (Humanitarian Logistics System)

Chào mừng bạn đến với tài liệu kỹ thuật của dự án Humanitarian Logistics. Đây là một hệ thống được thiết kế để thu thập và phân tích dữ liệu từ mạng xã hội (Twitter, YouTube, Facebook, TikTok) nhằm hỗ trợ công tác cứu trợ nhân đạo trong các tình huống thiên tai hoặc khẩn cấp.

1. Kiến trúc Tổng thể (Clean Architecture)

Dự án được xây dựng dựa trên nguyên lý Clean Architecture, giúp tách biệt mã nguồn thành các lớp (layers) để dễ dàng bảo trì, kiểm thử và mở rộng.

  • Domain Layer: Chứa các quy tắc nghiệp vụ cốt lõi (Entities) và các giao diện (Interfaces).
  • Application Layer: Điều phối luồng dữ liệu và thực thi các ca sử dụng (Use Cases/Services).
  • Infrastructure Layer: Cài đặt chi tiết các công cụ bên ngoài (Crawlers, Clients, Database, Config).
  • Presentation Layer: Giao diện người dùng (REST API và JavaFX GUI).

2. Chi tiết các Package

2.1. Domain Layer (com.hust.logistics.clean.domain)

Đây là lớp quan trọng nhất, không phụ thuộc vào bất kỳ thư viện bên ngoài nào.

  • entity/SocialPost.java: Đại diện cho một bài đăng trên mạng xã hội (ID, nội dung, nền tảng, thời gian).
  • entity/AnalysisResult.java: Kết quả phân tích (Loại phân tích, nội dung phản hồi, điểm số tin cậy).
  • gateway/SocialMediaCrawler.java: Interface định nghĩa cách thu thập dữ liệu.
  • gateway/AnalysisClient.java: Interface định nghĩa cách gửi dữ liệu đi phân tích (ví dụ: qua GPT AI).

2.2. Application Layer (com.hust.logistics.clean.application)

Lớp này chứa logic xử lý các tác vụ phân tích cụ thể.

  • service/LogisticsService.java: Service trung tâm điều phối việc thu thập dữ liệu và chạy các tác vụ phân tích.
  • task/AnalyticsTask.java: Interface chung cho các loại phân tích.
  • task/SentimentTrendTask.java: Phân tích xu hướng cảm xúc của người dân.
  • task/DamageAssessmentTask.java: Đánh giá mức độ thiệt hại dựa trên nội dung bài đăng.
  • task/ReliefAnalysisTask.java: Phân tích nhu cầu cứu trợ.

2.3. Infrastructure Layer (com.hust.logistics.clean.infrastructure)

Lớp này thực hiện các kết nối kỹ thuật thực tế.

  • crawler/CrawlerFactory.java: Khởi tạo Crawler phù hợp cho từng nền tảng.
  • crawler/impl/GenericSocialCrawler.java: Cài đặt chung cho việc thu thập dữ liệu mạng xã hội.
  • crawler/impl/YoutubeAdapter.java: Chuyển đổi dữ liệu từ YouTube sang định dạng chuẩn của hệ thống.
  • client/GptAnalysisClient.java: Sử dụng API của GPT để phân tích văn bản.
  • config/AppConfig.java: Quản lý các tham số cấu hình hệ thống (từ khóa, thời gian, API keys).

2.4. Presentation Layer (com.hust.logistics.clean.presentation)

Nơi người dùng tương tác với hệ thống.

  • gui/MainView.java: Controller chính cho giao diện JavaFX.
  • rest/LogisticsController.java: Cung cấp các API REST cho phép tích hợp với các hệ thống khác.

3. Luồng hoạt động (Workflow)

  1. Người dùng nhập từ khóa và thời gian trên JavaFX GUI.
  2. LogisticsService nhận yêu cầu, yêu cầu CrawlerFactory tạo Crawler.
  3. Dữ liệu từ mạng xã hội được thu thập và chuẩn hóa thành danh sách SocialPost.
  4. Service chọn một AnalyticsTask (ví dụ: Đánh giá thiệt hại).
  5. Task gửi dữ liệu đến GptAnalysisClient để xử lý bằng AI.
  6. Kết quả trả về được hiển thị lên màn hình hoặc trả qua API.

4. Thành phần AI (logistics-ai)

Bên cạnh mã nguồn Java, hệ thống còn tích hợp một module Python (main.py) chuyên trách các mô hình học sâu (Deep Learning) để tiền xử lý hoặc phân tích nâng cao.

Tài liệu này được biên soạn để hỗ trợ đội ngũ phát triển nắm bắt nhanh cấu trúc dự án.
